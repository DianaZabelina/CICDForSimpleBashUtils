### Настройка SSH
- Установим и настроим SSH-сервер на обеих машинах.
- На первой машине переключим текущего пользователя на _gitlab-runner_ и создадим SSH-ключ:
```
sudo su gitlab-runner
ssh-keygen -t rsa -b 2048
```
- Командой `ssh-copy-id adrienek@192.168.100.2` скопируем публичный ключ на удаленную машину, чтобы разрешить доступ без пароля: \
  ![part5_9](screenshots/Part5_9.png)
- Проверим, что SSH-ключ работает корректно: \
  ![part5_10](screenshots/Part5_10.png)
- На второй машине создадим SSH-ключ и командой `ssh-copy-id adrienek@192.168.100.1` скопируем его на удаленную машину:
  ![part5_11](screenshots/Part5_11.png)
- Изменим владельца директории, куда будут скопированы файлы, полученные после сборки (артефакты), на текущего пользователя:
```
sudo chown -R $(whoami) /usr/local/bin
```

## Part 6. Дополнительно. Уведомления
- Настроим уведомления об успешном/неуспешном выполнении пайплайна через бота с именем «[nickname] DO6 CI/CD» в _Telegram_. Текст уведомления должен содержать информацию об успешности прохождения как этапа CI, так и этапа CD.
### Создание Telegram бота и получение ID
- Откроем _Telegram_, найдем бота _@BotFather_ и запустим его: \

- Создадим нового бота командой `/newbot`. Зададим имя согласно заданию и юзернейм (должен быть уникальным и заканчиваться на _bot_): \

- Найдем бота _@getmyid_bot_ и запустим его для получения ID: \
  ![part6_3](screenshots/Part6_3.png)
### BASH-скрипт
- Напишем bash-скрипт, который будет отслеживать статус выполнения пайплайна и отправлять уведомление через бота: \
  ![part6_4](screenshots/Part6_4.png)
  - __api_url__ содержит URL для отправки сообщений через Telegram Bot API;
  - __CI_JOB_STATUS__ переменная окружения GitLab CI/CD, которая содержит статус выполнения задания;
  - __CI_JOB_STATUS__ переменная окружения GitLab CI/CD, которая содержит имя стадии, к которой относится текущее задание;
  - `curl -s -X POST "$api_url"` выполняет HTTP POST-запрос к Telegram Bot API для отправки сообщения;
  - `-d chat_id="$chat_id"` передает ID чата, куда будет отправлено сообщение;
  - `-d text="$message"` передает текст сообщения.
- **Примечание**: На скриншоте выше токен и ID замазаны вручную. После получения совета по защите чувствительных данных скрипт был переработан — актуальная версия считывает значения токена и ID из файла _.env_. Такой подход позволяет не хранить приватные данные в открытом виде в коде.
- Добавим в _.gitlab-ci.yml_ запуск bash-скрипта после каждого этапа: \
  ![part6_5](screenshots/Part6_5.png)
  ![part6_6](screenshots/Part6_6.png)
  - __.notify: &notify__: определяет шаблон, который содержит команды для установки прав на выполнение скрипта _notify_script.sh_ и его запуска.
